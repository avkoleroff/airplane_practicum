# Документация проекта

## 1. А что вообще мы делаем?

Аэропорт работает по суточному расписанию полётов (`schedule.txt`). Каждая строка расписания - заявка на взлёт или посадку с плановым временем, авиакомпанией, номером рейcа и т.п.

**Правила модели:**

- Моделируемый период — 24 часа (1440 минут) от выбранного времени начала.

- Число полос (2 - 10)

- Время двигается шагами (1 – 5 – 10 минут)

- Реальное время вносит отклонения от расписания: для **вылетов** — только задержки, нормальное распределение на `[0, range]` для **прилётов** — задержки и досрочные прибытия, симметричное нормальное распределение. Хвосты распределений обрезаются по границам диапазона. `range` задаётся пользователем (5–180 минут).

- Диспетчер ведёт две очереди (на взлёт и на посадку). На каждом шаге готовые заявки назначаются на свободные полосы в порядке FIFO (first in – first out) по времени готовности; любая заявка занимает первую свободную полосу.

- После завершения операции полоса выдерживает интервал безопасности (сепарация, все как в real life) перед следующей операцией.

- В модели всегда действуют случайные блокировки полос (погода/аварии): каждая свободная полоса блокируется с небольщой вероятностью за шаг моделирования на случайные N минут.

- Обслуженной считается заявка, операция по которой **завершилась** до конца моделируемых суток.

**Собираемая статистика:** число обслуженных заявок, число взлётов и посадок, максимальная и средняя задержка вылетов, максимальная и средняя длина очереди, процент занятости каждой полосы и средняя занятость всех полос, журнал событий (блокировки, начала и завершения операций).

## 2. Диаграмма классов

### Backend

```
simulation - ядро модели (simulation.h)
   step(), snapshot(), is_finished(); ГСЧ — отклонения и блокировки;
   суточный цикл; сохраянет статистику
	владеет: parameters ────── параметры эксперимента: N полос, шаг,
   │                           range, время старта,
   │                           расписание deque<timetable>
   └── загружает через ── schedule_loader ── статический загрузчик:
       │                   файл → vector<timetable>, валидация строк,
       │                   перенос рейсов раньше старта «на следующие сутки»
       └── создаёт ── timetable ── заявка: рейс, тип операции, отклонение,
           │                       готовность, назначение полосы, задержка;
           │                       from_line() — парсер строки расписания
           └── владеет ── timeclock ── модельное время: минуты в сутках +
                                       счётчик дней, парсинг "HH:MM",
                                       операторы < и +

── владеет ── dispatcher ────── очереди departure/arrival (deque<timetable>);
   │                             assign(now): FIFO по готовности →
   │                             первая свободная полоса; count_ready()
   └── владеет ── runway (vector, N штук) ── полоса: состояние
       │           FREE / OCCUPIED / BLOCKED, tick(minutes),
       │           cooldown-интервал после операции, учёт занятости
       └── владеет ── runway_operation ── текущая операция: рейс, старт,
                                          плановое время, длительность, остаток

── формирует ── simulation_snapshot ── граница «модель → UI» (snapshot.h),
    │                                   не зависит от SFML и ГСЧ
    ├── runway_snapshot ─────── срез состояния полосы
    ├── completed_operation ─── завершённая операция (для диаграммы Ганта)
    ├── sim_event ───────────── строка журнала событий
    └── simulation_stats ────── агрегированная статистика прогона
```

```

│   общий сценарий мыши; чистый виртуальный draw(); защищённый onClick()

├── SpinBox ───── счётчик [-] значение [+]: min/max/шаг, форматтер значения
└── ChipGroup ─── группа чипов с одиночным выбором (шаг моделирования)

setup_screen (render.cpp) ─────── экран настроек: владеет Panel root с
│                                 SpinBox×3, ChipGroup, Button, Label
visualizer_screen (render.cpp) ── экран симуляции:
 ├── владеет ── Panel root ──────── кнопки «Новый эксперимент» / «Стоп» / «Пауза»
 ├── ссылается ── simulation ────── шагает модель, снимает снапшоты

 └── использует ── AircraftSprite ── рисует силуэты самолётов
```

## 3. Спецификации основных классов

### Ядро модели (`classes/`)

**`timeclock`** — модельное время суток с учётом перехода через сутки. Хранит минуты в пределах дня (`time`, 0–1439) и счётчик дней (`day`). Конструктор из строки `"HH:MM"` валидирует формат и диапазон. `add(delta)` сдвигает время с переносом дня (корректно работает и с отрицательными сдвигами — досрочные прилёты). `as_int()` возвращает абсолютное время в минутах (`time + day*1440`), `as_string()` — формат `"HH:MM"`. Определены операторы `<` и `+`.

**`timetable`** — одна заявка на взлёт или посадку (одна строка расписания). Поля из файла: плановое время, тип операции (`operation_type::DEPARTURE` / `ARRIVAL`), авиакомпания, номер рейса, тип ВС, длительность операции. Поля, заполняемые моделью: отклонение `deviation`, время готовности `ready_time = scheduled + deviation`, фактические время начала/окончания, индекс назначенной полосы. Статический `from_line(line)` разбирает строку расписания с полной валидацией (формат времени, тип операции D/A, положительная длительность, отсутствие лишних полей) и бросает `runtime_error` с понятным сообщением. `shift_days()` переносит заявку на следующие сутки. `clamp_ready(min)` подтягивает готовность к началу моделирования. `assign(runway, start)` фиксирует назначение. `get_delay()` — задержка относительно расписания. Оператор `<` сортирует по `ready_time`, затем по плановому времени — используется для FIFO-порядка очередей.

**`schedule_loader`** — статический загрузчик расписания. `load(path, start_time)` читает файл построчно, пропускает комментарии (`#`) и пустые строки, парсит каждую строку через `timetable::from_line` (ошибки завёрнуты в исключение с номером строки), переносит рейсы раньше `start_time` на следующие сутки. Возвращает вектор заявок; пустое расписание — ошибка.

**`parameters`** — параметры эксперимента, собранные на экране настроек: число полос (2–10), интервал между операциями на полосе (мин), шаг моделирования (мин), диапазон отклонений (мин), время начала. Хранит загруженное расписание (`deque<timetable>`, отсортированное по готовности). `load_schedule(path)` загружает и сортирует расписание; вызывать нужно после установки времени начала.

**`runway`** — одна взлётно-посадочная полоса. Состояние (`runway_state`) вычисляемое: `BLOCKED` (идёт блокировка), `OCCUPIED` (выполняется операция), иначе `FREE`. `available()` дополнительно требует нулевого cooldown — интервала безопасности, который выставляется равным `separation_min` при завершении операции. `start_operation(op)` занимает полосу, `start_block(duration)` блокирует. `tick(minutes)` продвигает все таймеры полосы на `minutes`, учитывает занятость (`busy_minutes`) и возвращает `true`, если операция завершилась на этом шаге.

**`runway_operation`** — данные текущей операции на полосе: рейс, тип (взлёт/посадка), момент начала, плановое время, полная длительность и остаток `remaining_min` (по нему определяется завершение).

**`dispatcher`** — диспетчерская логика. Владеет вектором полос и двумя очередями заявок (на вылет и на прилёт). `add_request()` распределяет заявку по очередям (очереди должны быть отсортированы до начала моделирования). Ключевой метод `assign(now_min)`: в цикле берёт раньше всех готовую заявку из двух очередей (FIFO по `ready_time`), находит первую свободную полосу (`find_available_runway`), назначает заявку, заполняет `runway_operation` и запускает операцию; возвращает вектор начатых на этом шаге заявок. Если свободных полос нет — оставшиеся заявки продолжают ждать. `count_ready(now_min)` считает готовые, но ещё не назначенные заявки (текущая длина очереди).

**`simulation`** — ядро модели, суточный цикл работы аэропорта. Конструктор принимает `parameters` с загруженным расписанием, генерирует случайные отклонения по правилам ТЗ (см. п. 1: разные нормальные распределения для вылетов и прилётов с обрезкой хвостов), пересортировывает заявки по фактической готовности и передаёт их диспетчеру. `step()` — один шаг модельного времени: (1) продвинуть полосы через `tick`, завершившиеся операции зафиксировать в статистике и журнале; (2) разыграть случайные блокировки свободных полос (они всегда активны — часть модели); (3) назначить готовые заявки через `dispatcher::assign`, записать события начала операций с задержками; (4) снять статистику очередей; (5) по достижении 1440 минут от старта выставить флаг завершения. `snapshot()` формирует полный снимок состояния (`simulation_snapshot`) со всей статистикой: обслужено заявок, взлётов/посадок, максимальная и средняя задержка вылетов, максимальная и средняя длина очереди, занятость каждой полосы в процентах (`busy_minutes / elapsed * 100`) и средняя по всем полосам. Генератор случайностей — `std::mt19937` с инициализацией от `std::random_device`, поэтому каждый прогон уникален.

**Снапшот-структуры (`snapshot.h`)** — граница между моделью и интерфейсом: `runway_snapshot` (состояние полосы), `completed_operation` (завершённая операция для диаграммы Ганта), `sim_event` (строка журнала), `simulation_stats` (агрегированная статистика), `simulation_snapshot` (всё вместе). Не зависят ни от SFML, ни от генераторов случайностей — UI получает только данные.

### Интерфейс (`ui/`)

**`Widget`** — абстрактный базовый класс всех элементов интерфейса. Хранит позицию, размер, флаги видимости/доступности/наведения/нажатия. `handleEvent()` реализует общий сценарий «наведение → нажатие → отпускание внутри = клик» и уважает `m_visible` (невидимый виджет не рисуется и не реагирует на мышь). Чистый виртуальный `draw()`, защищённый виртуальный `onClick()`.

**`Panel`** — контейнер виджетов: рисует подложку с рамкой (опционально) и передаёт события детям в обратном порядке добавления (верхние получают событие первыми). `addWidget<T>()` принимает `unique_ptr`, забирает владение и возвращает сырой указатель для настройки.

**`Label`** — статичная текстовая подпись; `setText()` пересчитывает размер виджета по фактическим границам текста, `setFontSize()` корректно сохраняет кириллицу (round-trip через UTF-8).

**`Button`** — кнопка с текстом и колбэком `onClick`; поддерживает акцентный стиль (`setAccent(true)` для основного действия) и четыре визуальных состояния: покой / наведение / нажатие / недоступна.

**`SpinBox`** — числовой счётчик с кнопками «−» и «+»: границы min/max, шаг, необязательный форматтер значения (например, `"07:00"` для часов), колбэк `onChange`.

**`ChipGroup`** — группа чипов с одиночным выбором (радиокнопки); используется для выбора шага моделирования.

**`Theme`** — единая палитра (12 цветов: фоны, акцент с состояниями, тексты, граница) и ленивая загрузка шрифта `Arial.ttf` (один экземпляр на программу). Сопутствующие хелперы: `toSfString()` — обязательная конвертация UTF-8 → `sf::String` для корректной кириллицы (SFML трактует `std::string` как ANSI), `centerText()` — центрирование текста в прямоугольнике.

**`AircraftSprite`** — самолёт-силуэт (вид сверху, нос вдоль +X) из `sf::ConvexShape`; рисуется с заданной позицией, поворотом, масштабом и цветом.

### Экраны (`render.cpp`)

**`setup_screen`** — форма настроек эксперимента (единственный экземпляр между входами на экран, значения сохраняются при возврате).

**`visualizer_screen`** — состояние экрана симуляции: снапшот модели, визуальные самолёты, кнопки управления временем, вся зональная отрисовка.

**`visual_aircraft`** — один анимированный самолёт на полосе (позиция пересчитывается каждый кадр от модельного времени — движение плавное даже при крупном шаге). Три функции-экрана: `render_headspace`, `render_parameters`, `render_visualizer`; переключение между ними выполняет `main.cpp` через перечисление `window_status` (`WAITING` / `NEXT_STEP` / `EXIT`).

## 6. Пользовательский интерфейс

Окно — полноэкранный режим, система координат зафиксирована на 1920×1080 через `sf::View`, поэтому вёрстка не зависит от реального разрешения монитора. Тёмная тема, весь текст — шрифт Arial с поддержкой кириллицы.

**Экран 1 — заставка.** Название проекта, тема работы, авторы, кнопки «Начать» и «Выход» (Esc и крестик окна также закрывают программу).

**Экран 2 — настройки эксперимента.** Форма из четырёх параметров: число полос (SpinBox 2–10), шаг моделирования (чипы 1 / 5 / 10 минут), время начала моделирования (SpinBox 0–23 часа, формат `HH:00`), диапазон отклонения от расписания (SpinBox 5–180 минут). Случайные блокировки полос всегда активны (часть модели). Кнопка «Запустить эксперимент» загружает расписание и переходит к симуляции; ошибки файла или расписания выводятся красным текстом прямо на форме. Значения формы сохраняются при возврате с экрана симуляции.

**Экран 3 — визуализация симуляции.** Разбит на зоны:

- **Шапка**: крупные модельные часы, статус («Ход моделирования» / «Пауза» / «Остановлено» / «Завершено»), параметры прогона (старт, шаг, N) и кнопки управления — «Новый эксперимент», «Стоп», «Пауза».

- **Аэродром** (основная зона): по полосе на каждую ВПП — цветной индикатор состояния (зелёный — свободна, оранжевый — занята с номером рейса и остатком времени, серый — блокировка с остатком), осевая разметка, номер полосы и текстовый статус справа. По занятой полосе движется силуэт самолёта: вылет — слева направо (голубой), посадка — справа налево (жёлтый); самолёт появляется на пороге и проезжает полосу за время операции. Наведение на движущийся самолёт показывает всплывающую подсказку с номером рейса и типом операции.

- **Журнал событий**: последние 9 событий модельного времени — блокировки полос, начала операций с фактической задержкой, завершения взлётов/посадок.

- **Статистика** (правая колонка): обслужено заявок (из общего числа), взлётов/посадок, текущие очереди на взлёт и посадку числом, максимальная и средняя задержка вылетов, максимальная и средняя длина очереди, средняя загрузка полос и индикатор-полоска загрузки каждой ВПП в процентах.

- **Диаграмма Ганта** (нижняя зона): по строке на полосу, часовой масштаб на сутки; завершённые операции — сплошные прямоугольники (синие — взлёт, оранжевые — посадка), текущая операция — растущий прямоугольник с белой обводкой; легенда и подписи часов.

Сутки моделирования проходят примерно за 3 минуты реального времени при любом шаге; между шагами модельное время интерполируется, поэтому часы, самолёты и Ганта двигаются плавно.

По завершении суток всплывает **итоговый оверлей**: затемнение, панель результатов (обслужено заявок, взлёты/посадки, задержки, очереди, загрузки полос с индикаторами) и кнопка «Новый эксперимент» — возврат к экрану настроек с сохранёнными значениями.
